01 / ROLE

这不是单一的数据分析岗

岗位把数据工程、日常分析、轻量建模和业务落地放在一起。核心判断标准不是“用了多复杂的模型”，而是数据是否可信、结果是否可验证、建议是否能进入业务流程。

01 · DATA先把数据做对采集、统一口径、去重、校验、监控时效性。
02 · ANALYSIS再把问题讲清定位异常批次、拆分原因、形成日报与运行报告。
03 · MODEL用模型减少人工特征、标签、训练、阈值、时间回测、Bad Case 回流。
04 · BUSINESS接进真实流程服务行情预警、对客报价、风险敞口和平盘建议。

先看清岗位的难点：“数据标注、跑批、评测”是数据侧工作；“独立训练、回测并落地异常交易模型”已接近应用算法职责。新人要补的不只是模型，还包括 FX 报价、敞口、交易成本、时间序列防泄漏和风控边界。
02 / FX BASICS

先读懂一笔 EUR/USD 报价

EUR/USD = 1.0850 表示 1 欧元可兑换 1.0850 美元。EUR 是基础货币，USD 是计价货币；价格上涨表示欧元相对美元升值。

市场报价：EUR/USD 1.0849 / 1.0851

BID · 市场买入 EUR1.0849
ASK · 市场卖出 EUR1.0851
mid = (1.0849 + 1.0851) / 2 = 1.0850　·　spread = 0.0002 = 2 pips

EUR/USD 通常把小数点后第 4 位视为 1 pip：0.0001。日元货币对通常看第 2 位，不能统一乘 10,000。

六个高频概念

中间价（Mid）Bid 与 Ask 的中点，常用于算收益率；它不一定是实际成交价。
点差（Spread）Ask − Bid，是交易成本和流动性的重要信号；通常越窄越容易成交。
收益率（Return）比较相邻时点的价格变化；模型常用收益率而不是绝对汇率。
波动率（Volatility）一段时间内收益率的离散程度；高波动不等于方向一定上涨。
流动性（Liquidity）能否用较小成本快速成交；可从点差、深度、报价更新频率观察。
敞口（Exposure）持有某种货币后，汇率变化可能带来的盈亏风险。
对客报价市场为 1.0849 / 1.0851，平台给客户 1.0847 / 1.0853。报价要覆盖市场点差、波动风险、平盘成本和业务利润。
一笔交易客户按 1.0853 买入 EUR 100,000；平台随后按市场 Ask 1.0851 买回 EUR 对冲。暂不计手续费和滑点，毛利约为 (1.0853 − 1.0851) × 100,000 = 20 USD。
平盘客户买入欧元后，平台形成欧元空头敞口；在市场买回欧元，把风险降到限额内。平盘不等于每笔客户订单都立即一一对冲，也可先内部撮合相反方向的客户流。
03 / DATA

一行行情数据，先过五类校验

FX 近乎全天连续交易，但周末、节假日和不同市场时段仍有正常空档。先统一时区和交易日历，再判断“缺失”；否则会把正常休市误报成数据事故。

01原始接入供应商、交易系统、支付订单
02口径统一UTC、币对方向、精度、字段
03质量校验价格、时间、重复、跨源一致
04特征表收益率、点差、波动、时效
05标签表故障、人工复核、业务结果
06训练回测只用当时可见数据
07跑批 / 服务分数、原因码、阈值
08监控回流漂移、误报、漏报、Bad Case
QUOTE SCHEMAevent_ts · receive_ts · symbol · bid · ask · provider · depth / volume · quote_id · ingest_batch
MODEL TABLEsymbol · minute · mid · spread_pips · return_1m · vol_30m · quote_age_ms · gap_ms · cross_source_dev · label
准确性bid > ask 必错；与可信来源偏差过大需复核。
完整性按币对 × 市场时段看缺口，不只算整表非空率。
及时性receive_ts − event_ts 衡量报价到达延迟。
唯一性用 provider + quote_id 去重；重复到达不等于新行情。
一致性统一 UTC、币对方向和小数精度，再做跨源比较。

SQL · 去重并生成逐笔特征

WITH q AS (
  SELECT *, (bid + ask) / 2 AS mid,
    (ask - bid) * 10000 AS spread_pips,
    EXTRACT(EPOCH FROM (receive_ts-event_ts))*1000 AS age_ms,
    ROW_NUMBER() OVER (
      PARTITION BY provider, quote_id ORDER BY receive_ts
    ) AS rn
  FROM fx_quote_raw
  WHERE bid > 0 AND ask >= bid
)
SELECT *, LN(mid / LAG(mid) OVER (
  PARTITION BY symbol, provider ORDER BY event_ts
)) AS return_1
FROM q WHERE rn = 1;

教学示例使用 EUR/USD 的 pip 换算；生产中需按币对维护 pip_size，并处理乱序与迟到数据。

Python · 按时间训练与定阈值

features = ["return_1", "spread_pips",
            "age_ms", "cross_source_dev"]

train = df[df.event_ts < "2026-07-01"]
valid = df[df.event_ts.between("2026-07-01", "2026-07-31")]
test  = df[df.event_ts >= "2026-08-01"]

model.fit(train[features])
valid_score = -model.score_samples(valid[features])
threshold = np.quantile(valid_score, 0.999)
test["pred"] = -model.score_samples(test[features]) >= threshold

阈值在验证集确定，测试集只验收；上线阈值还要结合误报处理成本和漏报损失。

日常报表至少按币对、供应商、小时切片：记录行数、缺失率、重复率、负点差数、P95 延迟、价格异常数和跨源偏差。总体均值会掩盖单一币对或单个数据源的事故。

04 / CASE

完整案例：识别一条错误行情

先做规则基线，再决定是否上模型。错误行情是“市场数据本身不可信”；异常交易是“订单或账户行为可疑”，两者不能共用一套标签。

A · 本案例行情异常

输入是报价流；识别坏点、陈旧报价、重复、跨源偏离和点差突增。标签来自供应商事故、跨源核验和人工复核。

B · 另一任务异常交易

输入是订单、账户与设备行为；识别异常金额、频率、地域、账户关系或偏离历史习惯。需要合规规则和调查结果，不能只看价格。

EUR/USD · 1 分钟报价 · Provider A

以下数字为教学示例

1. 看到什么

10:30 突然上跳，下一分钟又恢复；同时 Provider B/C 的中位数仍为 1.08515。需要判断这是真实行情还是 A 源坏点。

2. 把现象变成特征

1 分钟对数收益率ln(1.0950 / 1.0850) = 0.00917 ≈ 0.917%
点差(1.0952 − 1.0948) × 10,000 = 4 pips
跨源偏差|1.0950 − 1.08515| × 10,000 = 98.5 pips
稳健异常分0.00917 / (1.4826 × MAD 0.00010) ≈ 61.9

3. 规则、模型和人工怎样配合

规则基线跨源偏差 > 10 pips，且单源独有 → 立即告警或降权。
模型补充把收益、点差倍数、延迟、缺口、跨源偏差输入 Isolation Forest；有稳定标签后再试树模型。
人工闭环结合新闻、其他数据源和供应商状态复核；确认后写入 label 与 reason_code。

“10:31 恢复原位”可用于事后确认标签，但 10:30 实时告警时还看不到未来。把它放进在线特征就是数据泄漏。

输出：anomaly_score=0.98 · action=downweight_provider_a · reason=cross_source_spike。下游聚合价临时降低 A 源权重，而不是让模型直接修改成交记录。
05 / EVALUATION

模型怎么训练，结果怎么算好

时间序列不能随机打乱后切分。训练只能看过去，验证集用于选模型和阈值，测试集只做最后一次验收；上线后还要持续监控。

BASELINE

规则 / 统计阈值

滚动中位数、MAD、跨源偏差和业务限额。透明、上线快，适合先验证问题是否真实存在。

适合：坏点、负点差、数据延迟、硬性风控规则
NO LABEL

无监督异常模型

Isolation Forest 学“多数正常样本”的分布，给少见组合更高异常分；它只说明少见，不自动等于错误。

适合：标签稀缺、先缩小人工排查范围
WITH LABEL

监督学习模型

用已复核的异常 / 正常样本训练分类器。重点是标签定义、类别不平衡和跨时间稳定性。

适合：标签口径稳定、异常模式可重复
1–6 月 · TRAIN
7 月 · VALID
8 月 · TEST

测试集：100,000 条，真实异常 100 条

真实异常真实正常模型报异常8040模型报正常2099,860

不是只看准确率

精确率 Precision80 / (80 + 40) = 66.7% · 报出来的告警有多少是真的
召回率 Recall80 / (80 + 20) = 80% · 真异常抓住了多少
准确率 Accuracy99,940 / 100,000 = 99.94% · 看似很高，但异常极少时会误导
业务指标误报 40 条、漏报 20 条；还要看每日误报量、检测延迟与损失金额
未来函数用未来价格、事后标签或完整日统计预测当下。
成本漏算策略回测未计点差、手续费、滑点和成交失败。
基线缺失复杂模型没超过“上一期波动率”或简单规则。
只看均值总体变好，但某币对、时段或数据源明显退化。

若预测波动率，可看 MAE / RMSE 并对比“沿用上一窗口波动率”的朴素基线；若输出交易策略，还要看净 P&L、最大回撤、换手率和含成本后的稳定性。模型分数高不等于一定赚钱。

A1 / OVERVIEW

JD 里的 AI，其实是两条路线

第一条是用专用模型处理 FX 数值数据，是岗位核心；第二条是让通用 Agent 调用数据、模型和报表工具，负责把工作流程执行完。

CORE · PREDICTION

传统机器学习：负责算结果

从历史行情、订单和账户行为中学习规律，输出行情异常概率、未来波动、交易风险分或建议点差。常用的可能只是 Isolation Forest、LightGBM、XGBoost 或时间序列模型，并不一定需要大语言模型。

示例输出　高波动概率 76% · 行情异常概率 8% · 建议点差 2 → 3 pips
WORKFLOW · EXECUTION

通用 Agent：负责调用和组织

理解“检查今日 EUR/USD”这样的自然语言任务，按照既定流程查询数据、调用异常模型、执行回测、拉取 Bad Case，最后生成可复核的报告。它不替代数值模型，也不应绕过交易与风控系统。

示例输出　Provider A 10:30 出现 17 条跨源异常，建议降低聚合权重并人工复核
一句话：专用模型负责“算得准”，Skill 负责“告诉 Agent 怎么干”，MCP / API 负责“让 Agent 能调用系统”，Agent 负责“把任务执行完”，风控规则负责“限制它不能乱干”。
A2 / STACK

五个组件，各自解决一个问题

把所有东西都叫 AI 会失去边界。下面这五层组合起来，才是一套能落地、能审计的 FX AI 应用。

01 · 专用模型预测器根据数值特征给出预测、概率或异常分。score_fx_anomaly(features)
02 · SKILL工作手册保存稳定术语、检查顺序、阈值原则和报告格式。先统一 UTC，再检查 Bid/Ask
03 · MCP / API工具接口连接行情库、模型服务、回测系统和审批系统。query_quotes() · run_backtest()
04 · AGENT操作员理解目标，选择工具，串联步骤并解释结果。查询 → 分析 → 复核 → 报告
05 · 风控系统刹车控制额度、权限、人工审批、日志和回退。不允许 Agent 直接改原始数据

MCP 是标准化连接方式，不等于行业知识，也不等于预测模型。它让模型能够调用外部工具；实际的价格计算、风控判断和交易执行仍由明确的业务服务完成。

A3 / RUN

一个 Agent 怎样完成每日 FX 检查

用户只给任务目标，Agent 根据 Skill 拆步骤；实时数据来自 MCP / API，异常判断来自专用模型，最终结果保留数据来源与计算过程。

01读取任务检查今日 EUR/USD 数据与模型
02查询数据通过 MCP 读取行情和运行日志
03执行质检缺失、重复、负点差、P95 延迟
04调用模型异常分、跨源偏差、波动预测
05拉取 Bad Case定位币对、时段、数据源与原因码
06生成报告结论、证据、建议、人工待办
输入任务“检查今天 EUR/USD 的数据质量和异常模型运行情况。”
Agent 输出接入 864 万条报价；重复率 0.03%；Provider A 在 10:30 出现 17 条跨源异常；模型 Recall 从 81% 降至 74%，下降集中在亚洲早盘。
执行边界Agent 可以生成“降低 A 源权重”的待审批建议，但不能直接删除原始行情、修改成交记录或自主下单。
A4 / PLACEMENT

行业知识不应该全部塞进 Skill

内容放在哪里，取决于它是否稳定、是否实时、是否需要计算，以及是否会产生真实业务动作。

稳定定义与 SOP → Skill币对方向、字段口径、检查顺序、报告模板、升级规则。
实时数据 → 数据库 + MCP / API行情、订单、敞口、模型运行状态不能写死在 Skill。
大量内部材料 → 知识库 / 检索制度、历史复盘、供应商文档按需检索，并返回来源。
预测与打分 → 机器学习模型异常概率、波动预测、风险评分和建议点差。
多步骤协调 → Agent理解任务、选择工具、检查中间结果、整理报告。
真实动作 → 业务系统 + 审批报价、平盘、冻结账户等操作必须受权限、限额和审计控制。
A5 / JD

回到岗位：面试重点不是只讲 Agent

该 JD 把 Agent 场景列为可选能力之一，但把训练、调优、回测、异常识别和落地验证写成核心职责。只讲 Skill / MCP，会漏掉最重要的数值建模部分。

优先级 01数据与特征行情和订单怎么清洗、对齐、校验，特征何时可见。
优先级 02建模与回测预测目标、标签、时间切分、基线、误报漏报与成本。

优先级 04Agent 自动化用 Skill 固化流程，用 MCP 连接数据与模型，自动完成分析报告。
