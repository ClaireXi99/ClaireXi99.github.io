通用准备

多模态数据：从采买到评测

面试时先讲任务和样本单元，再讲格式、流水线和指标。图片、视频、音频加一句描述只是其中一种数据形态。

一、任务与输入输出

任务输入 → 输出样本与关键点

对比预训练 / 检索

输入：图片、视频片段或音频片段 + 文本
输出：匹配分数或共享向量

media_uri + caption + pair_quality需要正样本，也要控制难负样本；文本与媒体“有关”不等于能准确描述。

媒体描述 Captioning

输入：图片、视频片段或音频片段
输出：一条或多条自然语言描述

media_uri + captions[]多参考描述能覆盖同一内容的不同合理表达；不能只用单一字符串匹配评估。

文生图 / 文生视频 / 文生音频

输入：文本提示词及可选控制条件
输出：媒体内容

prompt + media_uri + aesthetic / safety / motion tags描述应覆盖主体、属性、关系、风格和时序；还要区分技术质量与语义对齐。

多模态理解 / QA

输入：媒体 + 问题 + 可选字幕或 ASR
输出：答案、证据和时间段

media_uri + question + answer + evidence_span只有答案没有证据，很难判断模型是真理解还是利用语言先验猜中。

检测 / 定位 / 跟踪

输入：图片或视频 + 类别或文本查询
输出：框、掩码、轨迹或起止时间

media_uri + annotation + coordinates / timestamps标注必须绑定坐标系、帧率和时间基准；转码后帧号可能整体漂移。

不同模态的样本粒度

图片

样本单元
单图、图像区域或多图序列
关键字段
宽高、格式、颜色空间、EXIF、OCR、感知哈希、人物/隐私、安全标签
描述方法
主体—属性—动作—关系—场景；需要时增加区域级描述和文字转录。
常见坑
网页 alt-text 常是 SEO 文案或文件名；高 CLIP 相似不代表无水印、无偏见、无重复。

视频

样本单元
原视频 → shot / event clip → 关键帧；不是默认把整条视频当一个样本
关键字段
容器/编码、时长、FPS、分辨率、音轨、shot 边界、时间戳、运动量、关键帧
描述方法
静态场景、主体动作、事件顺序、镜头变化分层记录；长视频用 dense caption。
常见坑
字幕只是说了什么，不等于画面发生了什么；固定秒切片会截断动作并制造错配。

音频

样本单元
录音、语音段、声学事件或重叠事件窗口
关键字段
采样率、声道、位深、时长、响度、削波、静音、SNR、VAD、说话人、事件时间
描述方法
ASR transcript 与 acoustic caption 分字段：前者写“说了什么”，后者写“听到什么”。
常见坑
重采样和响度归一可能改变任务信号；单标签会丢失同时发生的多个声音。

二、推荐数据格式

大规模训练通常采用“对象存储中的媒体 + Parquet/JSONL manifest + WebDataset TAR shards”。媒体与结构化元数据分离，通过稳定 ID、URI 和哈希关联。

WebDataset：适合训练时顺序读取，同一 key 对应媒体、JSON 和文本，按 TAR 分 shard。

Parquet/Arrow：适合元数据筛选、统计、审计和分区扫描。

JSONL：适合逐条交换和调试，并使用固定 schema。

血缘：保留 raw → normalized → clip → annotation 的父子关系。

三、业内常见的大型数据集

图片—文本

LAION-5B

约 58.5 亿图文对大规模视觉语言预训练与数据过滤研究

规模大但来自网页；URL 可失效，文本噪声、许可、隐私和偏见必须重新审查。

DataComp CommonPool

约 128 亿候选图文对固定模型与算力，对比数据筛选策略

价值在“数据策略可比较”；构建时包含 NSFW 检测、评测集去重和人脸模糊。

COYO-700M

约 7.47 亿图文对图文对预训练，带多种元属性

不要只保留图片和 caption；可用于筛选的尺寸、相似度、水印等元属性同样重要。

视频—文本

WebVid-10M

约 1,000 万视频—文本对视频语言预训练、文生视频

股票素材标题与视频常有相关性，但仍需检查模板化标题、下载失效和许可范围。

HowTo100M

约 1.36 亿片段，来自约 122 万教学视频视频—语言表示学习

ASR 天然是弱监督，时间对齐有噪声；讲话内容可能领先或落后于实际动作。

HD-VILA-100M

约 1.03 亿片段，约 37.15 万小时高分辨率视频语言预训练

高分辨率不等于高语义质量；仍要处理字幕错配、静态片段和来源风险。

InternVid

700 万以上视频、2.34 亿片段、约 76 万小时视频理解与生成

体现了可扩展路线：视频切片、模型生成细粒度 caption、相关性与美学过滤，再做下游验证。

音频—文本

AudioSet

约 208 万个 10 秒片段，632 类本体音频事件分类与弱监督预训练

多标签、弱标注、真实环境混音；适合事件识别，不应把类别标签当完整音频描述。

AudioCaps

约 4.6 万音频片段及人工描述自动音频描述

基于 AudioSet；不同 split 的参考描述设置可能不同，训练与评测必须严格遵守版本和 split 协议。

Clotho

4,981 条 15–30 秒音频、24,905 条描述音频描述与音频—文本检索

每段五条人工描述，能观察同一声音的合理语言差异，适合多参考评测。

AudioSetCaps

约 190 万音频—描述对大规模音频语言预训练

自动 caption 扩规模有效，但必须保留生成模型、Prompt、置信度并以人评/下游任务校准。

四、从采买到可训练数据

  1. 01 目标与样本定义

    先写模型任务、数据域、样本粒度、覆盖维度、拒收项和验收指标。视频究竟按整条、shot 还是事件切片，必须在采买前确定。

    闸门：输出 data spec、taxonomy、样例输入输出和边界例。

  2. 02 采买与权利核验

    供应商提供来源链路、授权范围、地域/期限、人物肖像与声音同意、删除机制；禁止把“网上可下载”当成“可训练”。

    闸门：每个 asset 有 source_id、license_id、consent/provenance 状态和可删除键。

  3. 03 入湖与原始层冻结

    原文件只读保存，计算 SHA-256；元数据进 Parquet/JSONL。媒体与 manifest 分离，避免 base64 塞进表格。

    闸门：数量、字节数、哈希、可解码率和来源账单对得上。

  4. 04 技术清洗与切分

    解码、转码、抽帧/VAD/shot detection、时长与质量过滤；同时做精确、感知和语义去重。原始与派生资产保持父子关系。

    闸门：每个拒收样本有 reason_code；转码参数、工具版本和时间映射可追溯。

  5. 05 预标注与任务分发

    ASR、OCR、检测器、VLM/音频语言模型先生成候选；按置信度、长尾和模型分歧分流给人工，而不是把模型结果直接当真值。

    闸门：机器标签标明 model/prompt/version/confidence，不覆盖人工原始标签。

  6. 06 试标、正式标注与仲裁

    先小规模试标，依据分歧修改 guideline；主观任务采用多标与盲评，争议样本进入专家仲裁。

    闸门：金标命中率、IAA、一致性切片、返工率达到阈值后才放量。

  7. 07 质检、切分与冻结

    自动规则 + 分层抽检 + 下游小模型验证。train/val/test 按源视频、创作者或事件簇切分，不能随机拆相邻片段。

    闸门：测试集与训练集做跨模态近重复检查，冻结 dataset version 和 dataset card。

  8. 08 交付与闭环

    交付 shard、manifest、schema、统计报告、许可清单、处理版本和已知限制；线上 bad case 回流为新切片或回归集。

    闸门：可重放、可增量、可删除、可回滚；任何样本能追到源和每一步处理。

五、数据集与模型怎么评测

评测对象评测集 / 切片方法与判断

数据本身

供应商验收集、分层抽检集、去重审计集、许可/隐私审计集

可解码率、schema 完整率、重复率、pair alignment、质量分布、覆盖率、长尾占比、IAA、金标准确率、拒收/返工率质量分不能只报平均值，要按来源、语言、时长、场景、人物属性、难度等切片。

图文描述 / 检索

COCO Captions、Flickr30K，外加业务黄金集

描述：CIDEr、SPICE、BERTScore/CLIPScore + 人评；检索：Text→Image 与 Image→Text 的 Recall@1/5/10、MedRn-gram 指标奖励措辞相似，CLIPScore 可能漏掉细节错误；关键属性与关系仍需人评。

视频描述 / 检索 / 理解

MSR-VTT、VATEX；理解使用 Video-MME；长视频另建时间证据集

Caption 指标、双向 Recall@K、QA 准确率；按短/中/长视频和是否需要音频拆分视频级随机切分会把同源片段泄漏到测试集；必须按 source video 或事件簇隔离。

文生视频

VBench / VBench++ 提示词集 + 业务 prompt 集

主体/背景一致、运动平滑、动态程度、画质、美学、文本一致、安全；自动指标 + 盲测 pairwise单一总分会掩盖“画面漂亮但不动”或“动作大但主体崩坏”，必须报告维度和置信区间。

音频事件 / 描述 / 检索

AudioSet eval、AudioCaps、Clotho，外加噪声/重叠事件业务集

分类：mAP、macro/micro F1；描述：SPIDEr、FENSE、CLAPScore + 人评；检索：双向 Recall@KASR 正确不代表声学描述正确；事件存在、顺序、声源关系和幻觉要独立检查。

数据版本 A/B

固定模型结构、初始化、算力、训练步数和超参，只替换 dataset v1 / v2，同时比较总体指标、关键切片、收敛速度、长尾能力和置信区间。

六、三个完整 Case

Case A：为文生视频采买并生产视频—文本数据

  1. 先按题材、镜头、运动、主体数量和风险等级定配额；供应商按源视频交付，不直接交随机切好的片段。
  2. 源视频冻结后做 shot detection，再结合运动量和最短完整动作规则生成 clip；保留原视频 ID、起止时间和音轨映射。
  3. caption 分三层：静态可见内容、时序动作/事件、摄影与风格；字幕和 OCR 单独保存，不能混进视觉事实。
  4. 用 VLM 预标注，人工验证主体、数量、动作、方向、前后顺序和不可见推断；低置信或高价值长尾双标。
  5. 测试集按源视频/创作者隔离。验收同时看解码率、重复率、caption 事实错误、时序完整性、分布覆盖与下游小规模训练增益。

Case B：构建环境声音—文本数据

  1. 先区分任务：音频事件分类、音频描述、ASR 和声源定位需要不同标签，不能用一个 caption 代替全部监督。
  2. 切片以事件为中心，保留事件起止、重叠关系、前后顺序和背景声；记录采样率、声道、响度、削波、静音与 SNR。
  3. ASR transcript 只记录语言内容；acoustic caption 写“远处警笛逐渐接近，前景有人说话”，禁止凭场景常识补不可听见内容。
  4. 自动音频标签和生成 caption 作为预标注，人工重点复核稀有事件、重叠声音和模型分歧；测试集保留多参考描述。

Case C：网页图文对清洗

  1. 下载前保留 URL、页面上下文、许可和抓取时间；下载后记录内容哈希，处理死链、占位图、广告和追踪像素。
  2. alt-text 只是弱标签。先过滤文件损坏、低分辨率、水印/隐私/安全，再做感知去重和图文相关性评分。
  3. 模型重写 caption 时保留 original_caption 与 synthetic_caption，标出模型版本；事实性抽检优先检查数量、属性、文字和关系。
  4. 不要只用 CLIP 阈值一刀切：它可能牺牲小众文化、文本密集图和长尾概念，应结合覆盖率与下游任务共同定阈值。

七、面试表达

  1. 多模态数据的第一步不是选格式，而是定义样本单元和监督目标。整条视频、shot、事件 clip 是三种不同数据。
  2. 我会把媒体资产、annotation 和 provenance 分开管理：媒体可复用，标签可多版本，来源和删除权不能丢。
  3. ASR 是语言通道，audio caption 是声学通道；字幕是视频里的语言证据，不是视觉描述。
  4. 去重至少分 exact、perceptual 和 semantic 三层，而且 train-test contamination 要跨模态查：媒体近重复、caption 改写都可能泄漏。
  5. 自动打标提高吞吐，不产生金标。机器标签必须带模型、Prompt、版本和置信度，并用人评金标持续校准。
  6. 我不会只报整体平均质量，会按来源、模态、时长、语言、场景、难度和风险切片，否则均值会掩盖长尾问题。
  7. 数据质量最终要用下游效用验证：同模型、同算力、同超参，只替换数据版本，看目标任务是否真实提升。
  8. 评测集要按源实体隔离。把同一视频的相邻片段随机分到 train 和 test，指标会很好看，但结论是假的。
