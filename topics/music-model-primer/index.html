01 / MODEL MAP

先把模型拆成五个模块

下面是当前整曲生成常见的代表性分层，不是所有模型的固定结构。核心是把“写什么”和“声音怎么实现”分开。

CONDITION用户条件Query · 歌词 · 曲风 · 参考音频 · BPM / Key
→
PLANNER结构 / 旋律规划段落、歌词时序、旋律、和弦；可由 LM 或符号模型生成
→
REPRESENTATION紧凑音乐表示Codec token · semantic token · 连续 latent · MIDI / ABC
→
GENERATOR声学生成器自回归 Transformer，或 Diffusion / Flow DiT
→
DECODER音频解码VAE / Codec decoder / Vocoder → WAV
训练时
真实音频可见：从音频提取目标 token / latent，计算预测误差，反向传播更新参数。
推理时
真实音频不存在：模型根据条件预测计划和音乐表示，再从 token 或噪声生成波形。
Tokenizer / Codec把高采样率波形压成低帧率表示；token 越少越省上下文，但重建细节可能下降。
Transformer网络结构，不等于训练目标。它既能做“下一个 token”，也能作为 Diffusion Transformer。
Diffusion / Flow从噪声逐步走向连续音频 latent；训练预测噪声、v 或速度场，推理依赖采样步数与求解器。
Conditioning条件可通过拼接、Cross-Attention、ControlNet 或参考 token 注入；关键是时间对齐和训练覆盖。
02 / PARADIGMS

同是 Transformer，预测对象可能完全不同

先看“输入条件、模型预测什么、用什么 loss”，再判断它属于哪条路线。

路线模型预测典型训练目标推理方式主要取舍
自回归（AR）
DISCRETE		下一个 codec / semantic tokenL = −Σ log p(zₜ | z<ₜ, c)逐步采样，常用 temperature、top-k / top-p、KV Cache结构规划直接；长序列慢，早期错误会继续传递
扩散（Diffusion）
CONTINUOUS		噪声、v，或干净 latent随机时间步加噪后的回归损失从噪声多步去噪，可加 CFG每一步可并行处理整段 latent；步数决定速度与质量
流匹配（Flow Matching）
CONTINUOUS		噪声到数据之间的速度场L = E ||vθ(xₜ,t,c)−uₜ||²数值求解 ODE；可蒸馏到少步路径更直接、少步潜力高；仍依赖 VAE 与条件质量
混合级联（Hybrid）
AR + FLOW		先预测语义 / 旋律计划，再渲染声学 latentToken CE + Flow / Diffusion loss 分阶段训练规划 → 渲染 → 解码长程结构与音质解耦；模块接口误差成为新瓶颈

MusicGen

JD 经典路线
WAV → EnCodec 4 码本 / 50 Hz → AR Transformer → WAV

32 kHz 音频经 RVQ 变成并行码本序列，使用交错 pattern 预测。论文的 30 秒音频对应 1,500 个自回归时间步。

Riffusion 原始版

JD 经典路线
WAV → 频谱图 → 文本条件图像扩散 → 反变换

把时频图当图像生成，直观复用 Stable Diffusion；限制主要落在相位重建、长时连续性与音频专用表示。

Jukebox

JD 经典路线
WAV → 多层 VQ-VAE → 分层 AR prior → 逐级上采样

顶层先建长程音乐信息，底层逐级补声学细节；能生成带人声音乐，但层级多、采样计算量大。

03 / TRAIN

具体案例：一首 120 秒中文流行歌怎样进入训练

以下用“25 Hz 语义 token + Flow 渲染器”的现代混合架构演示。数值用于解释计算，模型层数、latent 维度和损失权重由具体实现决定。

训练条件 CONDITION

Query：女声中文流行，92 BPM，A minor；主歌克制，副歌加入鼓与电吉他。

歌词 / 结构：[intro] [verse] [chorus] [verse] [chorus] [outro]，保留完整歌词及段落时间边界。

监督目标 TARGET

Full mix：120 s · 48 kHz · Stereo。音质、歌词版本、结构、语种与 Meta 已通过门禁。

11.52M120×48,000×2 个标量采样值
3,000若语义流为 25 Hz：120×25
1 条条件、计划、token、latent 与音频同源对齐
样本读取音频 + Query + 完整歌词 + 结构 + Meta；按 Audio ID 取同一版本。
表示提取Tokenizer 得到 3,000 个语义 token；VAE 编码真实声学 latent。
LM 前向给定条件和前文 token，预测下一个语义 token 的概率分布。
Renderer 前向真实 latent 加噪；DiT 根据语义 token、歌词和时间步预测速度场。
更新与回归总 loss 反传；优化器更新参数；固定测试集检查音质、歌词与结构。

计算 01 · 自回归 token loss

真实下一个 token：842
模型给 token 842 的概率：p = 0.08
L_AR = −ln(0.08) = 2.526

反向传播会提高正确 token 在相同上下文下的概率。真实训练对 batch 内所有有效时间步求平均，padding 不计入。

计算 02 · Flow Matching loss

噪声 x₀ = −0.4，真实 latent x₁ = 0.6，t = 0.25
xₜ = (1−t)x₀ + tx₁ = −0.15
目标速度 uₜ = x₁−x₀ = 1.0
模型预测 0.7 → L_FM = (0.7−1.0)² = 0.09

这里只把一个 latent 维度缩成标量。真实损失会覆盖时间轴、通道、latent 维度和 batch。

训练时容易混淆的点：目标音频不会被梯度“修改”；变化的是 Tokenizer、LM 或 Renderer 的参数。分阶段系统通常先单独训练并冻结部分模块，再训练下游，最后做 SFT / 偏好对齐或联合微调。
04 / INFERENCE

同一个 case：没有目标音频时怎样生成整曲

推理只有用户条件和随机种子。完整歌曲的关键不是把 30 秒重复四次，而是先确定段落、歌词覆盖和能量变化，再渲染声音。

段落长度是该示例的计划，不是固定模板。歌词行需要被分配到可唱时间窗，否则会出现前 30 秒唱完、尾部漏唱或段落错位。

01 / NORMALIZE条件标准化统一语言、歌词标签、时长、BPM / Key 与参考音频。
02 / PLAN结构与旋律计划LM 输出段落、歌词时序；部分模型显式生成和弦 / ABC。
03 / SEMANTIC生成 3,000 个语义 token25 Hz × 120 s；逐步预测旋律、唱法和结构信息。
04 / RENDER噪声 → 声学 latentFlow / Diffusion 多步更新；同时读取 token、歌词与风格条件。
05 / DECODE48 kHz StereoVAE / Codec 解码，再做响度、削波、歌词覆盖与结构质检。
Temperature / top-p控制 AR token 多样性；过低趋同，过高可能结构漂移。
CFG / guidance增强文字条件；过高可能牺牲自然度或产生伪影。
Steps / solver决定 Flow / Diffusion 成本；少步需要蒸馏或专门训练。
Best-of-N多候选重排能抬高最终样本质量，但计算成本按 N 增长。
05 / JD COVERAGE

JD 中“懂模型”具体要能回答什么

不是背模型名，而是能从任务定义一路讲到表示、loss、采样、评测和部署瓶颈。

01

架构与表示

为什么不用原始 48 kHz 波形直接给 Transformer？Codec token、语义 token、连续 latent、MIDI 各保留什么、损失什么？

02

训练与调优

能写出 condition → target → prediction → loss；说明预训练、SFT、LoRA、DPO / RL 和质量课程分别解决什么问题。

03

可控生成

歌词、旋律、和弦、结构、音色、参考音频如何进入模型；静态全局标签与随时间变化的控制如何区分。

04

音频 / 音乐理解

BPM、Key、Chord、Beat、Structure、Lyrics alignment、Source separation 既能生产训练条件，也能定位生成 Bad Case。

05

多模态与编辑

文本成歌、清唱配伴奏、Cover、Repaint、续写、分轨的输入输出不同；图像条件也可能先转成音乐描述，而非直接进音频模型。

06

压缩、加速与部署

区分 AR 的 token 数 / KV Cache 与 DiT 的采样步数；记录硬件、精度、batch、显存、冷 / 热启动和质量回归。

实时系数 RTF生成耗时 ÷ 音频时长。30 秒音频耗时 6 秒，RTF = 0.20；越小越快。
AR 优化降低 token rate、码本交错、KV Cache、量化、并行解码；检查结构与音质损失。
DiT 优化减少采样步数、蒸馏、改求解器、混合精度、编译 / TensorRT；必须复测伪影。
长音频优化全曲上下文、分段窗口与 overlap 各有取舍；跨段落连续性不能只靠 crossfade。
